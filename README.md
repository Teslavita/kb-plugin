# Плагин базы знаний Tesla Vita

Подключает Claude Code и Codex к базе знаний компании (https://kb.teslavita.space): MCP-сервер и навыки «спросить базу», «добавить в базу», «исправить ошибку в базе» (правка текста, названия и даты, замена файла, корзина на 30 дней) и «мои файлы и доступ к ним» (показать свои файлы, открыть или закрыть файл коллеге). Вход — рабочим аккаунтом Google через кабинет https://admin.teslavita.space; без входа плагин ничего не открывает. Доступ выдаёт администратор.

## Вопросы коллегам

С 0.6.0 через базу можно спросить коллегу: «спроси Костю, считаем ли от даты оплаты, это по TES-301». Вопрос появляется у адресата в Claude Code при запуске сессии (хук `SessionStart` плагина вызывает `tv-kb inbox --hook`), а с 0.6.1 и посреди открытой сессии: на его следующем сообщении (хук `UserPromptSubmit`, не чаще раза в минуту, только новое) Claude сначала отвечает на сообщение, потом говорит, что пришло. С 0.6.3 в свежем Claude Code вопрос всплывает сам, даже если человек ничего не пишет: мод плагина (`hooks/register.tsx`) раз в минуту спрашивает базу (`tv-kb inbox --peek`), показывает всплывающее уведомление о новом вопросе или ответе и строку над полем ввода с кнопкой «Показать», пока вопрос не отвечен. Только внутри Claude Code, без системных уведомлений компьютера. С 0.6.5 ответ держится в строке, пока вы не нажмёте «Понятно» на этом компьютере, даже если другая ваша сессия его уже видела. С 0.6.6 «Показать» раскрывает тексты прямо в строке, без Claude: работает и пока идёт ход, и в любом проекте. Работа на Tesla Vita (`bin/kb-work`) — это папка, путь к которой содержит TeslaVita или TvtApp, папка с файлом-отметкой `.teslavita` или репозиторий github.com/Teslavita. Вне работы на Tesla Vita хуки молчат и в разговор ничего не попадает, всплывает только строка. С 0.6.8 у вопроса в любом проекте есть кнопка «Предложить ответ»: черновик пишет сама база с вашим доступом (`tv-kb inbox --draft`), а не Claude текущей сессии, и показывает его в строке. «Отправить» отправляет его как ваш ответ (`tv-kb inbox --answer`), «Изменить» кладёт его в поле ввода. Без вашего нажатия ничего не уходит. Ещё вопрос виден строкой под ответами базы, а бот @teslavita_team_bot пишет ему в Telegram. Ответ возвращается так же. Чтобы получать сообщения в Telegram, один раз нажмите «Старт» у бота: кабинет → Оргструктура → своя карточка → «Подключить Telegram». В Codex вопросы видны строкой под ответами базы и по просьбе «покажи вопросы мне» (навык `kb-questions`).

## Claude Code

```bash
claude plugin marketplace add Teslavita/kb-plugin
claude plugin install teslavita-kb@teslavita
```

При первой сессии плагин сам скачает программу `tv-kb` и откроет в браузере вход в кабинет — рабочий аккаунт Google, затем «Разрешить». После этого переподключите сервер (`/mcp` → `teslavita-kb` → Reconnect) или начните новую сессию. Вход держит `tv-kb`: он живёт полгода и продлевается, пока базой пользуются, — входить каждый день не нужно.

Обновление: `/teslavita-kb:update` или

```bash
claude plugin marketplace update teslavita && claude plugin update teslavita-kb@teslavita
```

Автообновление включать не нужно: с 0.6.1 плагин при запуске сессии сам ставит `extraKnownMarketplaces.teslavita.autoUpdate: true` в `~/.claude/settings.json`, если его там нет, и один раз пишет об этом (так принято в команде: у всех по умолчанию). Тем, кто ещё на 0.6.0, нужен один раз `/teslavita-kb:update`. Если плагин устарел, база знаний сама скажет об этом в ответе.

Если вход слетел: `~/.config/tv-kb/bin/tv-kb login`, затем Reconnect. Подробно — в навыке `/teslavita-kb:update`.

## Codex

```bash
codex plugin marketplace add Teslavita/kb-plugin
```

В Codex: `/plugins` → установить `teslavita-kb`, начать новую сессию. Если вход не предложен сам: `codex mcp login teslavita-kb`. Codex обновляет плагины сам при каждом запуске; вручную — `codex plugin marketplace upgrade teslavita`.

## Выпуск новой версии

Запустите `scripts/set-version.sh 0.5.3` (своё число): оно меняет версию во всех пяти местах — `version` в `plugins/teslavita-kb/.claude-plugin/plugin.json` и `.codex-plugin/plugin.json`, два заголовка `X-Teslavita-Plugin` в `.mcp.json` и `plugin=` в `bin/kb-headers` — и проверяет, что число везде одно. Без аргумента скрипт только проверяет. База знаний читает версию из `plugin.json` этого репозитория и сравнивает с заголовком, который шлёт установленный плагин: если в каком-то месте число осталось старым, база говорит «вышло обновление» тем, у кого плагин уже свежий.
